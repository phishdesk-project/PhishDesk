# PhishDesk dataset v0: dataset card

A labelled email corpus for phishing triage research: training and evaluating the
PhishDesk baseline classifier and LLM analyzer. It combines real public emails with
synthetic emails from a deterministic generator.

**Exact counts, hashes and warnings live in [`docs/data/composition.md`](../docs/data/composition.md),
which is generated by a script.** The figures below are copied from the report of
2026-11-23; if they differ, the report is right.

| --- | --- |
| `data/labels/<source>.csv`: id, file hash, labels, hashed sender group | Raw public emails (`data/raw/public/`) |

Committed label files contain no senders, subjects, addresses or email text; a CI test
checks this.

## How to rebuild

From the repo root, with the virtual environment active:

```
python scripts/download_sources.py nazario spamassassin enron
python scripts/prepare_sources.py nazario
python scripts/prepare_sources.py spamassassin
python scripts/find_enron.py --urgent 150 --other 300
python scripts/generate_synthetic.py --count credential=65 --count payment=78 --count impersonation=39 --count urgency=48 --count benign=113 --count legit_urgent=60
python scripts/build_dataset.py
python scripts/dataset_stats.py
```

Downloads are checked against the SHA-256 hashes in `data/sources.json`, and every
committed label is checked against the hash of the email it describes, so a rebuild
either reproduces this dataset or stops with an error.

To label new emails: `make_label_sheet.py`, then `label_cli.py`, then `export_labels.py`
(see the labelling guidelines).

## Configuration

| Setting | Value |
| --- | --- |
| Synthetic generator | v0.1, 18 template families (2 active + 1 held back per category) |
| Held-back families | `cred-payroll-portal`, `pay-manager-gift-cards`, `imp-telecom-survey`, `urg-files-deleted`, `ben-order-confirmation`, `lu-timesheet-cutoff`: reserved for the Month 7 fresh test set, never generated by default |
| Split | seed 42; ratios 70/15/15 applied to real emails; synthetic records are train-only |
| Grouping | one group per synthetic template family; real emails grouped by hashed sender address; near-duplicates (shingle similarity >= 0.9) merged into one group; a group never spans two splits |
| Deduplication | exact duplicates (same normalised subject and text) dropped before splitting: 4 in v0 |
| Python | results above produced on Python 3.13; CI runs 3.11 and 3.13 |

## Labelling

- Real emails were labelled by person2 with the terminal tool `scripts/label_cli.py`,
  following the taxonomy decision record. Synthetic labels come from the template that
  generated each email.
- Confidence on real emails: 189 high, 4 medium, 0 low.
- **Inter-labeller agreement:** person1 independently labelled a seeded random sample of
  29 real emails (`data/labels/review-sample.json`): category agreement 22/29 (76%),
  tactics 21/29 (72%). All 9 disagreements were discussed and resolved in favour of the
  second labeller's labels, and the labelling rules were clarified; see the decision record.
  After resolution, the comparison against the committed labels shows 0 differences.

## Intended use

- Training and evaluating the PhishDesk baseline (TF-IDF + logistic regression) and
  the LLM analyzer, with results reported per category and per source.
- Not suitable for estimating real-world prevalence of phishing: the class balance is
  chosen, not sampled.

## Known limitations

- **Small real test set.** Dev (30) and test (26) contain real emails only, so every
  metric has a wide margin of error. Report counts alongside percentages.
- **Thin real categories.** Real examples: payment 11, impersonation 11, legit_urgent 11,
  urgency 2. Their training data is mainly synthetic, and dev/test hold only 1–2 of each,
  so per-category scores for them are not reliable in v0.
- **Urgency cannot be evaluated on real mail in v0:** it has no records in dev or test.
  This follows from the priority order, which assigns most threatening phishing to
  credential or payment. The urgency *tactic* is well covered: 28 real phishing emails
  carry it.
- **Legitimate mail is mostly from one company in 2001** (Enron 122, SpamAssassin 5).
  Modern business mail may look different.
- **Real phishing comes from one inbox** (Nazario, 2025, 66 emails), which is
  representative rather than exhaustive, and was hand-classified by its publisher.
- **Synthetic emails are cleaner than real ones** and come from only two active template
  families per category; a model can learn template wording. They are used for training
  only.
- **Labelled mainly by one person,** with a 15% double-labelled sample (76% category
  agreement before resolution, below the 85–90% target; see the decision record).
- **No QR-code examples** in v0.
- **English only.**
